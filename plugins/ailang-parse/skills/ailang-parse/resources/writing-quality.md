# Writing quality before document generation

Use this when authoring or substantially rewriting content, not when the task
is extraction or faithful conversion. Review the Markdown before formatting.

- Identify the intended reader, author and purpose. Write directly in the
  author's voice when appropriate; do not invent their experience or authority.
- Put the main finding, decision or request early. Make the introduction state
  the subject and scope without generic scene-setting.
- Read the title and headings as an outline. Each should accurately describe
  its section; avoid vague labels that need the body to explain what they mean.
- Preserve facts when simplifying: numbers, units, dates, comparison baselines,
  conditions and uncertainty. Keep recommendations distinct from established
  facts. A reference document supplies style, not new facts for this document.
- Give each paragraph a clear point and explain the relevant relationship.
  Use lists for distinct items or steps. Use tables for comparable records,
  values or options; do not turn long prose into cramped table cells.
- Use concrete nouns and verbs, descriptive link labels and meaningful image
  descriptions. Remove repeated conclusions, stock promotional language and
  unsupported claims. Preserve useful technical terms and the user's voice.
- Check source citations are readable and resolve to actual sources; internal
  tool citation tokens must not leak into the generated file.

Respect requested language, punctuation, colours and template styling. This
review is not a reason to restyle a supplied document or rewrite quotations.
When space is tight, preserve substance and improve flow before shrinking type.
After substantive revisions, recheck claims as well as the rendered layout.
